How to use this handbook

Work through the test cases in order, starting at TC-001. Each one says what to prepare, exactly what to click or type, and what you should see. After each test, choose Pass, Fail, Blocked (can’t be done yet) or leave it Not tested, write what actually happened, and note your screenshot file name. Everything you enter is saved automatically.

What AVAL does

A bridal-accessories shop. Customers browse, add items to a bag, and place an order without an account. Each order gets a private link (/o/…) where the customer chats with the artisan, pays through Razorpay and tracks delivery. Brides can also request a bespoke design and accept a quote. The shop owner runs everything from /admin.

Who uses it

  • Customer (guest, no login): browse, bag, checkout, order page, track order, custom requests, quotes.
  • Owner (admin): everything, including Settings and deleting coupons.
  • Staff (admin): orders, products, coupons, reviews; cannot save Settings or delete coupons.

There is no customer registration, login or profile screen, so those phases are not in this handbook.

UI checks vs database checks

Most checks are done by looking at the shop and the admin screens. Where a test needs to see stored data directly (stock movements, queued emails, staff accounts), open Prisma Studio with npx prisma studio. Those tests are tagged “Needs DB”.

How serious is a bug?

SeverityUse it whenAVAL example
CriticalMoney, customer data or ordering is broken; no workaround.Customer can pay less than the price; another person can read an order’s address; checkout crashes.
MajorAn important feature fails or gives wrong results; a workaround exists.Coupon not applied; stock not returned on cancel; admin can’t dispatch.
ModerateWorks but confusing, inconsistent or partly wrong.Wrong message text; filter count off; layout broken on one screen size.
MinorCosmetic; doesn’t stop anyone.Typo, spacing, icon misaligned.

Priority is how soon to fix: P1 before launch, P2 soon after, P3 when convenient. Usually Critical = P1, but a Minor typo on the checkout button can still be P1.

Release readiness

Assessment before your test pass: not ready to launch yet. The core order, payment and admin flows work in testing, but several things customers or the shop rely on are missing. Re-read this after your pass and add what you found.

Must fix before launch

  • Customers get no email or WhatsApp after placing an order; emails only send when the email job is run by hand.
  • Contact form doesn’t send messages anywhere.
  • Unpaid orders hold stock forever; add automatic expiry.
  • Real product photos (several products share the same photo).
  • Privacy policy, terms and returns pages (Razorpay requires them for live keys).
  • Razorpay live keys and the webhook URL on the deployed site; test one real ₹1 payment and refund.
  • Uploads saved to the server’s disk will be lost on most cloud hosts; move to cloud storage before deploying.
  • Change the seeded admin password; set your real WhatsApp number in Settings.

Should fix soon

  • Remove or finish the unlinked pages (/order-confirmation shows a fake order).
  • Refunds are manual; add a refund action or a clear checklist for staff.
  • Rate limits reset on restart; use a shared store in production.
  • No staff-management screen; staff accounts need the database.
  • Phone layout of the home page (sideways scroll found in the audit).
